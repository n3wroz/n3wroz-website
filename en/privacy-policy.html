POFRA MEDIA PLAYER – PRIVACY POLICY

Last updated: 25 November 2026

1. SCOPE AND APP FUNCTION

POFRA Media Player plays media files selected by the user on their device and media, M3U, or M3U8 links supplied by the user. The app does not itself provide TV channels, films, series, broadcasts, subscriptions, or media content. This policy describes the data practices of the current version of POFRA Media Player.

2. INFORMATION STORED ON THE DEVICE

The app stores user-saved playlist sources and links, favorites, playback history, and app preferences such as language in Android app-specific storage. A playlist URL supplied by a user may contain a username, password, access token, or other sensitive URL parameters. Users should add only trusted sources and take care when sharing playlist links.
POFRA does not provide user accounts, developer-operated cloud synchronization, or developer-hosted playlist storage. Android app backup is disabled in the project manifest. Local information can be removed by deleting the relevant entries in the app, clearing the app's storage in Android settings, or uninstalling the app.

3. MEDIA LINKS AND FILE ACCESS

When a user opens an internet link or playlist, the device sends a request to the server specified in that link. That server and relevant network providers may receive the device IP address, request time, requested address, and technical connection information. If credentials or access tokens are embedded in the URL, they may also be sent to that destination server. These third-party servers are not controlled by the developer.
The app supports HTTP and HTTPS for compatibility. HTTP is not encrypted; third parties on the same network or along the network path may be able to view or modify traffic. Use HTTPS whenever possible and do not put passwords or sensitive information in untrusted HTTP links.
Local media files are accessed only after the user selects a file through Android's system file picker. The source manifest does not request broad storage or location permission.

4. ADVERTISING AND GOOGLE SERVICES

The phone and tablet experience uses Google Mobile Ads GMA Next-Gen SDK 1.7.0 for banner and native ad placements and Google User Messaging Platform (UMP) 4.0.0 for privacy choices. UMP is called at app launch to refresh consent information and, where required, present Google's consent/privacy form. Mobile ad initialization is gated by UMP indicating that ad requests may be made.
Google's published GMA data disclosure states that, depending on SDK configuration and use, the SDK may automatically collect and share data such as approximate location inferred from IP address, app interactions (for example, app launches and taps), diagnostic information, and device/account identifiers (for example, advertising ID and app set ID) for advertising, measurement/analytics, and fraud-prevention purposes. Google states that SDK data is encrypted in transit using TLS. The applicable data categories and details can change by SDK version; consult Google's current disclosure for the version included in the release.

5. PERMISSIONS AND DATA SHARING

The QR scanner uses the camera only to read a POFRA Connect code selected by the user; the app does not upload or store a camera photo for this scan.

POFRA Connect allows an Android phone, tablet, or Android TV device to act as either sender or receiver. When receiver mode is started, the device opens a temporary local-network receiver and displays a device-specific QR code containing its local IP address, temporary port, and six-digit PIN. The QR/PIN session is valid for up to 10 minutes; the user can refresh the QR code to create a new PIN. The receiver accepts a media URL and title while the PIN is valid. The media file is not uploaded to or stored by the app; the receiver requests the stream directly from the source URL. The sender device sends the URL, title, and PIN to the receiver over the local network. The sender's local network address is processed to establish the connection. This local connection uses unencrypted HTTP; devices or people on the same Wi-Fi network may be able to observe the QR/PIN or media URL. Use a trusted private network and do not share the code publicly. Local file URIs are not sent. When Google Cast is selected, Google Play services discovers compatible receivers; the selected receiver may process the media URL, title, playback commands, and technical session data. Google Cast/Google Play services may process device, network, session, and diagnostic data under their own terms and privacy disclosures. The external receiver may connect directly to the media source. POFRA Connect transfers media links; it is not full-device screen mirroring.

The app uses internet access to open media sources selected by the user. It does not directly request location or broad storage permission; local files are opened after the user selects them through Android's system file picker. Third-party components such as advertising SDKs may process data or use permissions as described in their own documentation.
The app does not provide a synchronization service that sends local playlists, favorites, or history to a developer-operated server. When a user connects to a media source, connection information is shared with the relevant media provider. Advertising-related data may be processed by Google as part of its services.

6. RETENTION, DELETION, AND USER CHOICES

Local app records remain on the device until the user deletes them, clears app storage, or uninstalls the app. Users can manage favorites and saved playlists in the app and clear playback history. Data processed by Google's advertising SDK is subject to Google's retention, deletion, and advertising privacy practices; the developer does not directly control data stored in Google's systems. Users can manage advertising ID and ad-personalization preferences through the privacy settings offered by their device and Google account. The app presents UMP privacy options in regions where UMP indicates that an entry point is required.

7. SECURITY

App data is stored in Android app-specific storage, and Android backup is disabled in the project configuration. The app does not claim to apply separate end-to-end or file-level encryption to local records. HTTP media links are not encrypted; HTTPS should be preferred. No internet transmission or device can be guaranteed to be completely secure. Keep your device updated and do not enter access credentials into untrusted links.

8. CHILDREN AND ACCOUNTS

The current app version does not provide user account creation or account-based data synchronization. The publisher must separately and accurately declare the app's target audience and child-directed distribution settings in Google Play Console. If distribution to children is intended, advertising, consent, and data practices must be reassessed for those requirements.
